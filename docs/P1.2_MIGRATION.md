## 3. P0 Regression Checklist (Must Survive Migration)

Every item below was hardened during Phase 0 and must remain strictly functional across all migration steps:

- [ ] **Honest Detection Metrics**:
  - `aiProbability` reflects backend score without derived fallbacks (no synthetic `b.confidence / 100`).
  - `metrics` (perplexity, burstiness, consistency) reflects actual backend signals without hardcoded `{ perplexity: 0.5, ... }` defaults.
  - Absence of metrics renders: `"Signal breakdown unavailable for this analysis."`
  - Missing confidence score renders honest `"—"` rather than a fabricated percentage.
- [ ] **Sidebar Service Health Polling**:
  - Initial neutral status `'checking'` with `"Checking status…"`.
  - Polling `/actuator/health` every 60s with 5s timeout.
  - Proper status dots: green (`operational`), amber (`degraded`), red (`offline`), muted (`checking`).
  - Cleanup on unmount (`clearInterval`).
- [ ] **ProtectedRoute Destination Preservation**:
  - Unauthenticated access redirects to `/signin?next=<encodeURIComponent(pathname + search)>`.
- [ ] **401 Interceptor Next-Param & Re-entrancy Guard**:
  - Axios 401 response interceptor encodes destination into `/signin?next=...`.
  - Skips auth check endpoints (`/api/user/me`, `/login`).
  - Global `isRedirecting` lock prevents looping redirects.
- [ ] **Cookie & CSRF Participation**:
  - Explicit Axios settings: `xsrfCookieName: 'XSRF-TOKEN'`, `xsrfHeaderName: 'X-XSRF-TOKEN'`, `withXSRFToken: true`.
  - Request interceptor reading `document.cookie` for `XSRF-TOKEN`.
  - 403 treated as an API error without unintended signin redirect.
- [ ] **Auth Form Open-Redirect Protection & Notices**:
  - `SignIn.tsx` & `SignUp.tsx` validate `next` parameter against protocol-relative (`//`) or backslash (`\`) exploits.
  - Session expiration warning banner displayed when `sessionExpired=true`.
  - Redirects securely to `safeNext` after successful login or registration.

## 4. Step B Fix List & Decision Log

During Step B, review audited the canonical production pages and eliminated all P0-class fabrication leftovers:

### Exact File & Line References
1. `frontend/src/api/client.ts` (~lines 255–275):
   - Throws `new Error('The verification engine returned an unexpected response.')` if neither `payload.aiProbability` nor `payload.probability` is a finite number (removed `?? 0`).
   - `confidenceScore`: Populated **only** when `typeof payload.confidenceScore === 'number'`; otherwise `undefined`. Removed the synthetic `?? payload?.metrics?.consistency ?? aiProbability` chain. Field is optional in `DetectionResponse`.
   - `metrics`: Instantiated **only** when `perplexity`, `burstiness`, and `consistency` are all finite numbers in the payload; otherwise `undefined`. Removed `?? 0` defaults. Field is optional in `DetectionResponse`.
2. `frontend/src/pages/Detection.tsx` (~lines 80, 104, 346):
   - Line ~80: Removed canned string `'Analysis retrieved from workspace session.'`; `analysis` preserves actual string or `undefined`.
   - Line ~346: Render displays honest absence notice when `result.analysis` is missing: `"No analysis details were returned for this scan."`
   - Fresh analysis & session restore: Narrowed with explicit `resp.metrics &&` checks; preserves `"Signal breakdown unavailable for this analysis."` when metrics are absent.
3. `frontend/src/pages/History.tsx` (~lines 46–53, 90–98, 156–160, 171–194, 340):
   - Removed `: 50` default; `scoreValue` and `confidenceScore` are optional in `HistoryRecord`.
   - Unscored records display `scoreText: '—'` and honest neutral `verdict: 'Not scored'`.
   - Unscored records are disabled and non-clickable with tooltip `title="Score unavailable"`.
   - Sort guards updated: `'Highest score' -> (b.scoreValue ?? -1) - (a.scoreValue ?? -1)` and `'Lowest score' -> (a.scoreValue ?? 9999) - (b.scoreValue ?? 9999)`.
   - Removed `confidenceScore: scan.scoreValue / 100` mislabel; uses `scan.confidenceScore` when numeric, else `undefined`.
   - Removed canned analysis fallback string; passes `scan.analysis` directly.
   - Summary and aggregates filter strictly over numeric records only.
4. `frontend/src/pages/Dashboard.tsx` (~lines 50–54, 89–95, 114, 211):
   - Removed `: 50` default; `scoreValue` is optional in `ScanItem`. Unscored records show `'—'`, `'Not scored'`, and are non-clickable with `title="Score unavailable"`.
   - Line ~93: Kept `Math.round(b.confidence)` with explicit documentation: `// b.confidence stores the persisted probability (set at save time)`.
   - Line ~114: Replaced `confidenceScore: b.confidence / 100` mislabel with `typeof parsedResult.confidenceScore === 'number' ? parsedResult.confidenceScore : undefined`.
   - Summary statistics calculate over numeric records only.
5. `frontend/src/pages/Reports.tsx` (~lines 35–39, 60–65, 131, 186, 257, 286):
   - Removed `: 0` default; `score` is optional in `ReportItem`. All score displays render `'—'` when absent.
   - PDF export uses `activeReport.score ?? 'unscored'` in filename.
   - Removed synthetic score-derived interpretation paragraphs (`"Elevated probability of automated generation detected..."`); `interpretation` reflects `item.analysis` only.
   - Render and PDF export display honest absence notice when interpretation is absent.
   - Completely purged fake `status: 'READY' | 'DRAFT'` and `<Badge tone="green">READY</Badge>` from interface, mapping, and report list.
   - Removed `confidenceScore: activeReport.score / 100` mislabel.

### Decision Log
- **Decision (a): `confidenceScore` is engine-only (`"—"` until engine returns it)**. The detection engine (`/api/detect/bulk-ai`) produces `probability` and `metrics{perplexity, burstiness, consistency}` but does not produce a model confidence score. The client previously relabeled `metrics.consistency` or `aiProbability` as `confidenceScore`. This conflation has been eliminated; missing confidence renders as `"—"`.
- **Decision (b): Reports status badge removed**. There is no report processing lifecycle or asynchronous queue in the backend; hardcoded `'READY'` badges were fabricated visual chrome without operational meaning.
- **Decision (c): `b.confidence` kept as stored-probability fallback**. In `AiDetection.java`, Spring Boot sets `confidence = Math.round(dto.getAiProbability() * 100)` when persisting detections. Therefore, `b.confidence` represents the real saved probability score from the analysis and is valid to display as the score/probability fallback.
